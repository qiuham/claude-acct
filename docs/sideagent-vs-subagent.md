# sideagent 面板和 Claude Code 自带子代理逐项对照

结论：主界面横条那一行已经按子代理那一行重画，能照抄的都照抄了，中间那段也改成了同款进度短语。
详情页做不到一样：插件接口不让 sideagent 用子代理的“切换主视图”方式打开。

依据：

* 子代理那一行：Claude Code 2.1.316 程序代码。代码是打包压缩过的 JS，函数名是压缩后的名字。
  * 列表：`Xz`（子代理列表）、`Gle`（一行）、`Tqe`（右侧那段文字）。
  * 格式：`ln`（耗时）、`Bi`（词元数）、`Ny`（行首宽度）。
  * 进度短语：`[AgentSummary]` 一段（中间那段的进度短语）。
  * 活动描述：各工具的 `getActivityDescription`。
* sideagent：`mods/sideagents-panel/hooks/register.js`、`band-row.js`，插件版本 0.4.2。
* 标“推断”的没有在真终端里看过。

## 七、派活、追问、回报（Agent / SendMessage 的语义）

依据：2.1.316 程序代码里的完成通知（`jWt`、`bi`：`<task-notification>` 的各个标签）、
后台用量（`nbe`：`total_tokens`、`tool_uses`、`duration_ms`），以及本会话里 Agent 工具的参数说明。

| 项 | 子代理 | sideagent 现在 | 结果 |
|---|---|---|---|
| 派新活 | Agent：新开一个，上下文从零开始 | 号名 = 新开实例 | 已一样 |
| 追问 | SendMessage 给同一个：在跑就排到它下一个工具调用结束时送到（“Message queued for delivery to X at its next tool round. If it finishes first, it is resumed with the message and notifies again…”）；结束了就接着开（“Resuming agent X”） | 实例全名 = 追问，默认在下一个工具调用结束时送到，先做完就接着开再回报；退出了用它的 claude 会话 `--resume` 接着开；回话照这两句的意思写；`mode: "queue"` 只作显式选项 | 已一样（实测：退出后追问“上一轮回复了什么”，答对了） |
| 退出后还能查到会话编号 | 记录一直在 | 以前状态文件被并发写盖成残缺的，会话编号、代码版本、进程号都丢了，看起来像退出了；退出时也没留会话编号 | 已修：状态先写临时文件再换名，所有写入加锁；一拿到会话编号就记进 `<名字>/result.json`，退出时再记一次；`sideagent_status` / `sideagent_result` 对已退出实例也返回会话编号和代码版本 |
| `description` | 必填，3-5 个词，显示在列表里、写进完成通知的摘要 | 新增可选参数 `description`：横条中间没有进度短语时显示它，通知摘要也用它 | 已改；没做成必填（已定，见第八节 1） |
| `name` | 可选，起了名字列表里显示名字 | 可选参数 `name` | 已一样 |
| `model` | 可选（sonnet、opus、haiku） | 新增可选参数 `model`，传给这个实例的 claude；追问时沿用原来的 | 已改 |
| `subagent_type` | 选代理类型（Explore、general-purpose 等，各有提示词和工具） | 没有 | 已定，见第八节 2 |
| `isolation: worktree` | 可在临时 git 工作区里跑 | 没有 | 已定，见第八节 3 |
| 前台、后台 | 有前台和后台两种（推断：默认前台，等它做完才返回） | 默认后台（`background: true`），显式传 false 才在原地等 | 已定，见第八节 4 |
| 前台的回话 | 结果正文，加怎么继续它，加 `<usage>total_tokens / tool_uses / duration_ms</usage>` | 以前只有正文和“几轮、几毫秒” | 已改：正文 + “实例 ds#… 用 sideagent_send 接着问” + 同样格式的 `<usage>` |
| 后台的回话 | 说已在后台跑、会自动通知、不要轮询 | 以前只说“已接活、结果写在哪个文件” | 已改：说明会自动回报、不用轮询、怎么追问 |
| 完成通知 | `<task-notification>`：`task-id`、`status`、`summary`（`Agent "描述" finished`）、`note`、`result`（全文）、`usage`（`subagent_tokens`、`tool_uses`、`duration_ms`） | 以前是一段 1000 字以内的纯文本，没有用时和词元 | 已改：同样的标签和写法，包在跨会话消息里；结果最多 2 万字（已定，见第八节 5） |
| 失败通知 | `status failed`，摘要写 `failed: 原因` | 卡住时只报错给在等的调用方，后台派的不回报 | 已改：卡住时也发一条 `status failed` 的通知 |
| 被停掉的通知 | 停掉时也发一条（“was stopped by Claude / user”） | 不发 | 已定，见第八节 6 |
| 排队的消息 | 列表右侧黄色 `N queued` | 一样 | 已一样 |
| 打断 | 子代理没有“只打断这一轮”的操作（只能停） | 有 `sideagent_interrupt` | 多出来的功能，保留 |

## 八、用户已定（2026-11-01）

1. `description` 保持可选：不填就用交办的原话。
2. 不做代理类型（`subagent_type`）。
3. 不做临时 git 工作区（`isolation: worktree`）。
4. 默认后台。
5. 通知里的结果最多 2 万字。
6. 被停掉时不发通知：停是主会话自己做的。
7. 进度、事件文件退出后保留 1 天（以前是 5 分钟）。
